# engine — Interface

## Publishes
- **DMX frames** per universe to configured nodes: Art-Net (UDP 6454), sACN (UDP 5568 multicast/unicast), ENTTEC Pro serial. Framing in `cmdmx-protocols`; scheduling in the daemon.
- **IPC state** to clients (contract v0, to be specified in `specs/modules/ipc.md`):
  - `snapshot` on connect: settings (incl. `faders_per_page`), patch summary, pages, playback states (level, active), warnings.
  - `palettes` (PAL-25) in the snapshot and as a whole-list delta; palette use in the programmer state (PAL-26).
  - `undo` (IPC-31) in the snapshot and as a delta when a label changes: `{"undo": label|null, "redo": label|null}`; commands `undo`/`redo` (IPC-30), refused with "Nothing to undo"/"Nothing to redo". One history in the daemon for all clients (UNDO-15), emptied by `show.open`/`show.new` and a restart (UNDO-13).
  - `outputs` (IPC-20, OUT-33) in the snapshot and as a delta: one entry per node of the show, sorted by line then id: its fields (`id, line, enabled, kind` + `port_address, target` | `universe, priority, unicast` | `port`) plus `state` `Ok | Degraded | Stopped | Disabled` and an optional `detail`.
  - `output.add {line, kind, …}` / `output.edit {id, …}` / `output.remove {ids}` (OUT-34, undoable edits) and `output.ports` → `{"type":"ports","ports":[{path, product, vid, pid, enttec}]}` to the asking client (OUT-35).
  - `control` (CTL-39, VS7-02) in the snapshot and as a delta: `devices` `[{name, kind: midi|streamdeck, input, output, state: Ok|Missing|Disabled|Busy|Unsupported, enabled, mapping, errors}]` (a deck adds `model`, `verified`, `cols`, `rows`, `extras {dials, touch_keys, strip, info}`, `deck_page`, `deck_pages`, `brightness`, `keys: [{key, label, sub, halo: "#rrggbb"|null, level|null, state: off|inactive|active|held, fixed}]`, CTL-57, VS7-06), `mappings` `[{name, profile}]`, `learn` (armed action or null), `order` (CTL-31, the Mackie unit order, device names), `last_input` `{device, input, value}` (≤ 10/s; `value` is a number, or an OSC argument), `osc` `{enabled, port, feedback_port, allow, clients: [{address: "ip:port", last_heard: seconds|null, configured}], mapping, errors, error}`. Commands (class neutral, refusals are warnings): `control.enable {device, on}`, `control.assign {device, mapping}`, `control.learn {action, mapping?}`, `control.learn_cancel`, `control.deck {device, brightness?, page?}` (CTL-53 brightness 0..=100, CTL-67 page 1..=deck_pages; one of the two), `control.order {devices}` (CTL-31), `control.binding {mapping, input, deck_page?, action?, …options}`, `control.unbind {mapping, input, deck_page?}` (both pick the stored binding by `input` and `deck_page`, default 1; CTL-67), `control.mapping_new {name, device}`, `control.mapping_rename {name, to}`, `control.mapping_delete {name}`, `control.mapping_import {json, replace?}`, `control.osc {enabled?, port?, feedback_port?, allow?, clients?, mapping?}` (CTL-35, VS7-03; a bad value refuses the whole command); `control.mapping {name}` → `{"type":"control.mapping","name","mapping"}` to the asking client. Messages `Learned: …`, `… was …`, `<device> disconnected`, `<deck> is in use by another app; …`, `<device> is not supported` arrive as warnings.
  - `effect_catalogue` (FX-32) in the snapshot only (it never changes): `looks` `[{id (1-based), name, group, shape, attribute|null}]` and `shapes {wave, path, colour}`. The programmer view (IPC-11) gains `effects` (FX-33) `[{id, look, shape, attributes, members, positions (k/N), params, palette, current, colours, white_base}]`, `effect_wheels` and `runnable_looks` (catalogue ids some target can run; FXB-05); a snapshot palette with entries carries `effects [{look, shape}]`; never the clock, so running effects send no delta. While the effect wheels are on and an entry is current, `wheels` are Size, Speed, Spread, Phase, Width (Crossfade for ColourMix), Top, Beats, Wings, `value` the parameter as a fraction of its FX-06 range, `touched` true.
  - `delta` events: playback level/active changes, programmer, groups, `fixtures` after a patch change (PAT-09), warnings.
  - transport: WebSocket, JSON messages versioned with `"v": 1` (IPC-41; 1 since cells, IPC-42); loopback-only for the app (DECISIONS 2026-10-17). Remote clients (iPad/browser) later need a LAN listener with authentication.
- **MIDI out** to control surfaces: feedback after each tick per binding (fader/CC values, LEDs; `cmdmx-control::feedback`, VS7-02); Mackie Control encoding with VS1-07.
- **Show file** `<name>.cmdmx.json` (SHW-01), autosaved by the daemon.

## Consumes
- Library requests from clients, answered to the asker (LIB-14): `library.search`, `library.import_report`, `library.profile`, `library.save_profile`, `library.save_channel_list`.
- IPC commands from clients: the effect commands (FX-34): `effect.apply {look}` | `{shape, attribute?}` | `{palette}` (exactly one), `effect.set {param, value}` (`{"param":"spread","value":720}`, `"direction":"Bounce"`, `"speed_source":{"Bpm":1}`), `effect.select {entry}`, `effect.stop {group?}`, `effect.restart` (edits, undo labels "Effect <look>", "Effect <param>" coalescing per parameter), `effect.tap` and `effect.wheels {on}` (live); control actions `effect tap`, `effect restart`, `effect stop` (FX-35); `fader.set {playback, level}`, `grand_master.set {level}`, the programmer commands (IPC-13, 18, 23 `programmer.colour`, IPC-46 `programmer.ct_step {step}` (`cto_`/`ctb_` + `full|half|quarter|eighth`; `colour_model` also takes `Kelvin`; the programmer view carries `colour.kelvin`, rounded to 10 K or null, and `auto` on a wheel whose emitter is auto-mixed), IPC-47 `programmer.gel {range:"Lee", number}` and `library.gels {range:"Lee"}` (answered to the asker with `{type:"library.gels", range, gels:[{number, name, r, g, b}]}`; the programmer view's `colour.gel` names the reading), LIB-39 `profile.emitter {name, cie?}` (answered to the asker with `{type:"profile.emitter", name, cie, default_cie, status: auto|no_colour|outside_gamut}`), IPC-39 `programmer.set {attribute, value}`), IPC-48 `programmer.order {op}` (`Reverse|Shuffle|Sort|Revert`), `programmer.grid {wings?, groups?, blocks?, flip?}` (`{}` = off) or `{shortcut, n?, m?}` (`OddEven|OneIn n|NIn n m|Blocks n|Divide n|OutsideIn|InsideOut|Off`), `cue.order {list, cue, order: {item: k}}` (an edit step) and `effect.set` `order`/`flip`; the programmer view carries `grid` (null or `{wings, groups, blocks, flip}`), `stage` (null or *s*), `positions` (per selection item) and `position_count`, a `cue.view` its `order` (absent when none); control actions `order <op>`, `grid <shortcut>`, `patch.add/move/remove/renumber/name/change_mode/handle` (PAT-09), `patch.profile {profile}` (IPC-37, answered to the asker) and `profile.save {profile}` (IPC-38, LIB-25), `library.import_gdtf {path}` (IPC-45, LIB-34; answered to the asker with `library.imported {manufacturer, model, modes, replaced, report}`), `palette.record/apply/include/copy/move/renumber/delete/legend` and `settings.palette` (PAL-27); later `record.*`.
- MIDI in from any CoreMIDI device (raw packets → `cmdmx-control::midi::Decoder` → mapping → engine commands, VS7-02); mapping files in `~/Library/Application Support/CMDMX/control/` (or `<show-dir>/control/`), device choices in `state.json` under `control`.
- The QLC+ fixture set in `vendor/qlcplus/fixtures` (`scripts/fetch-qlcplus.sh`, pinned commit, Apache-2.0) and user profiles in `~/Library/Application Support/CMDMX/profiles/`.
- Fixture profiles in the own model (ADR-006, `fixture-library.md`): `cmdmx_core::profile::Profile::from_json` (validated, LIB-02); importers (QLC+, channel list, GDTF) convert into it. Scenario files may use the minimal `{ "attributes": [...] }` shape (one mode "default").

## Owns
- All lighting state: patch, programmer, palettes, cues, playbacks, pages, masters, output mapping, control mapping.
- The clock for the engine tick and all timing (fades, chases).
- The show file on disk.

## Does NOT handle
- Any rendering or window management.
- User-facing text/legends beyond storing them.
- Fixture library downloads (a client or separate tool fetches GDTF files; the engine loads from a folder).

## Assumes about environment
- macOS host (phase 1); the crates themselves are portable.
- Network interfaces reachable for UDP broadcast/multicast; serial device nodes under `/dev/cu.*`.
- MIDI via CoreMIDI through `midir` 0.11 in the daemon (macOS only; elsewhere no ports).
