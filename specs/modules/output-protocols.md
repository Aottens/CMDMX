# Module spec: output-protocols (OUT)

Owner: `cmdmx-protocols` (framing) and `cmdmx-daemon` (sockets, serial, scheduling). Status: **OUT-01..04, 11, 12, 14, 15 approved by owner 2026-10-16**; OUT-06/07/16..19 approved 2026-10-16; OUT-09/20..22 approved 2026-10-17; OUT-09/20 amended and OUT-23/24 added 2026-10-18 (owner, Eurolite MK2 on the Mac); OUT-24 amended 2026-10-21 (owner, VS4-05: own 30 ms timer); rest draft. References: Art-Net 4 specification (Artistic Licence), ANSI E1.31-2018 (sACN), ENTTEC DMX USB Pro API, Avolites Titan v19 manual *DMX Settings*.

## Purpose
Deliver each universe's frame to one or more *nodes* (Titan's model: lines → nodes). Framing is pure and byte-exact tested; I/O lives in the daemon and must never block the tick.

## Model
- A **line** is a universe produced by the engine (numbered 1..n, free numbering later).
- A **node** is a destination: `ArtNet { target: ipv4, port_address }` (broadcast or unicast is just the choice of target), `Sacn { universe, priority, multicast|unicast ip }`, `Serial { port, protocol: EnttecPro }`.
- A line may feed several nodes; a node belongs to one line.

## Acceptance criteria

### Art-Net
- **OUT-01** `artnet::art_dmx(universe15: u16, sequence: u8, physical: u8, data: &[u8]) -> Vec<u8>` produces: ID `"Art-Net\0"`, OpCode `0x5000` little-endian, ProtVer `14` big-endian, Sequence, Physical, SubUni (low byte), Net (high byte), Length big-endian (even, 2..512), then the data. Golden bytes for a 512-channel frame on universe 0 are in the test.
- **OUT-02** Sequence increments 1..255 and wraps to 1 (0 means "disabled"); the daemon keeps one counter per node.
- **OUT-03** Continuous mode: the daemon sends one ArtDmx per tick (40 Hz) to every enabled Art-Net node, whether or not the frame changed. This is the only mode in phase 1 and matches Titan's default "Continuous Art-Net DMX". The change-only mode is OUT-14.
- **OUT-04** Each Art-Net node has one IPv4 target; the socket has `SO_BROADCAST` set, so a target can be the limited broadcast `255.255.255.255` (default — reaches the Mac's primary LAN and a monitor on the same Mac), a directed broadcast (`2.255.255.255`, `192.168.1.255`, …) or a unicast node IP. Destination port 6454. Packets leave from an ephemeral source port, so an Art-Net monitor on the same Mac can own port 6454. Per-interface broadcast enumeration and ArtPoll/ArtPollReply discovery are later (OUT-10, not in phase 1; OUT-10 will also need to bind 6454).

### sACN (E1.31)
- **OUT-05** `sacn::data_packet(cid: [u8;16], source_name: &str, priority: u8, sequence: u8, universe: u16, data: &[u8]) -> Vec<u8>` produces a valid E1.31 data packet: Root layer (preamble `0x0010`, postamble `0x0000`, ACN packet identifier `"ASC-E1.17\0\0\0"`, flags+length `0x7xxx`, vector `VECTOR_ROOT_E131_DATA = 0x00000004`, CID), Framing layer (vector `0x00000002`, 64-byte UTF-8 source name zero-padded, priority, sync address, sequence, options, universe), DMP layer (vector `0x02`, address type `0xA1`, first address 0, increment 1, property value count = 1 + data length, start code 0 + data). Golden bytes in the test.
- **OUT-06** The daemon sends one E1.31 data packet per tick (40 Hz, continuous like OUT-03) per enabled sACN node. Default destination is multicast `239.255.{hi}.{lo}:5568` for universe `hi<<8|lo`; a node may instead have one unicast IPv4 target (port 5568). Multicast loopback is on, so sACNView on the same Mac receives it; TTL and outgoing interface are the OS defaults (interface choice is later). Packets leave from an ephemeral source port. The sequence number is per node, starts at 0 and wraps 255 → 0.
- **OUT-07** Priority defaults to 100 and is configurable 0–200 per node (Titan uses this for backup consoles). The framing clamps above 200; configuration rejects values above 200 instead of clamping them.

### ENTTEC Pro over serial
- **OUT-08** `enttec::send_dmx_frame(data: &[u8]) -> Vec<u8>` produces `0x7E`, label `6`, length LSB, length MSB (length = 1 + data.len(), data padded to at least 24 channels), start code `0x00`, data, `0xE7`. Golden bytes in the test.
- **OUT-09** Detection: the daemon lists serial ports with their USB info and picks the ones whose USB product string passes `enttec::is_pro_product_string` and whose path starts with `/dev/cu.`. With several matches it takes the lowest path and logs the others. It logs `serial: ENTTEC Pro "<product>" at <path>`. A port without a matching product string is never used, so an interface is never treated as ENTTEC Open DMX. *(Amended 2026-10-18.)* The owner's Eurolite USB-DMX512 PRO MK2 reports VID/PID `0403:6001` with the FTDI default product string `FT232R USB UART`, which Open DMX clones share, and it does not answer the ENTTEC "get widget parameters" request (probed at 9600..3000000 baud), so it cannot be told apart from an Open DMX clone and is not detected: it is used through `--serial <path>` (OUT-22, OUT-23) until the show stores the chosen port (OUT-13).
- **OUT-20** The chosen port is opened raw at **250000** 8N1 without flow control, with a 100 ms write timeout. Each tick hands the node one label-6 frame (OUT-08) of line 1, written on the node's own thread (OUT-11) at the rate of OUT-24. *(Amended 2026-10-18, was 115200 and every tick.)* 250000 is the Eurolite MK2's rate (manufacturer protocol sheet; the MK2 has a microcontroller behind an FT232R UART and ignores frames at 115200 — verified on the owner's dimmer). A 518-byte frame takes 20.7 ms at 250000; at 115200 it took ~54 ms and the writes timed out. Interfaces with an FT245 FIFO (ENTTEC Pro) ignore the baud rate.
- **OUT-21** Hotplug: no interface at startup is not an error; it is logged once (`serial: no ENTTEC Pro interface found`) and the daemon keeps looking. While there is no port, or after a write/open error (`Degraded`, OUT-12), it rescans at most once per second, so unplugging and replugging resumes output without a daemon restart.
- **OUT-24** The serial node writes on its own timer, not on the tick: its thread keeps the latest frame handed over (OUT-11) and writes it every 30 ms (`MIN_WRITE_INTERVAL`, a calibration constant), counted from the start of the previous write, so about 33 Hz whatever the tick rate. Two writes are never less than 30 ms apart; the frame written is the latest one handed over, at most one tick old. Nothing is written before the first frame arrives; opening the port writes at once (OUT-21 rescans unchanged). A panic in a write is caught and the timer carries on (OUT-11). Testable with an injected clock: frames handed over every 25 ms give writes at 0, 30, 60, 90 ms …, each carrying the newest frame handed over by then. *(Added 2026-10-18 as "skip a frame handed over within 30 ms of the previous write", which gave every second tick = 20 Hz; amended 2026-10-21, VS4-05, because a dragged fade on the RGBL par at 361 showed visible steps at 20 Hz.)* The MK2 restarts its DMX frame when a new USB frame arrives: at 40 Hz an LED par at 361 flickered, even at full and from a clean C sender, while 10, 20, 25, 30 and 33 Hz and a single held frame were steady (the halogen dimmers at 185 hid it). Art-Net and sACN stay at 40 Hz on the tick.
- **OUT-23** When detection finds no interface but there are FTDI ports (USB VID `0x0403`) on `/dev/cu.*`, the once-logged OUT-21 line names each of them (lowest path first) instead of leaving the owner guessing: `serial: no ENTTEC Pro interface found; FTDI "<product>" at <path> not used (start with --serial <path> if it is a Eurolite USB-DMX512 PRO MK2)`, joined with `; ` for several ports. Those ports are still never opened (OUT-09).

### Scheduling and safety
- **OUT-11** Output I/O runs on its own thread(s); a slow or failing node never delays `engine.tick`. The tick hands each frame over through a bounded channel without blocking; when the output thread has not taken the previous frame yet, the new one is dropped (the next tick carries a fresh frame). A panic inside the output thread is caught, logged, and the thread carries on with the next frame.
- **OUT-12** On a send error (including failing to open the socket) the node is marked `Degraded`, the last frame is kept, the error is logged once per state change (`Ok → Degraded`, `Degraded → Ok`; a different error while degraded is not logged again), and sending retries every tick.
- **OUT-13** New show defaults: 16 lines; line n → Art-Net universe n-1 (net 0, subnet 0) *disabled* and sACN universe n *enabled*, mirroring Titan's defaults; serial node auto-assigned to line 1 when a known interface is present.

- **OUT-14** *(later, not in vertical slice 1)* Change-only mode (`continuous = false`): send only when the frame changed, plus a keep-alive at least every 800 ms. Needs per-node config in the show file.
- **OUT-15** *(vertical slice 1 only, superseded by OUT-13 once node config lives in the show file)* Without a show file the daemon outputs line 1 to one Art-Net node, port-address 0, **enabled**, target `255.255.255.255`. `--artnet-target <ipv4>` sets the target; `--no-artnet` disables the node. An unparsable target is a startup error (exit code 2), not a silent fallback.
- **OUT-16** *(vertical slice 1 only, superseded by OUT-13 once node config lives in the show file)* Without a show file the daemon outputs line 1 to one sACN node, universe 1, multicast, priority 100, **enabled** — alongside the Art-Net node of OUT-15. `--sacn-unicast <ipv4>` replaces multicast with that target, `--sacn-priority <0..200>` sets the priority, `--no-sacn` disables the node. An unparsable value is a startup error (exit code 2).
- **OUT-17** Source name is `ColourmotionDMX`. The CID is one fixed UUID compiled into the daemon (`c0105e00-d3a0-4c00-8000-000000000001`) until the show file stores a generated CID (SHW); a fixed CID keeps receivers seeing the same source across daemon restarts.
- **OUT-22** *(vertical slice 1 only, superseded by OUT-13 once node config lives in the show file)* Serial output is **enabled** by default with detection (OUT-09). `--serial <path>` skips detection and uses that device; a path that does not exist (yet) is `Degraded` and retried like OUT-21, not a startup error. `--no-serial` disables the node.
- **OUT-18** *(later)* On a clean shutdown the daemon sends three packets with the Stream_Terminated option bit per sACN node. Needs signal handling in the daemon.
- **OUT-19** *(later)* E1.31 universe discovery packets (universe 64214) every 10 s.
