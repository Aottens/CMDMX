# Where a redraw's cost goes — SNP-04 (2026-11-08)

UI-70. Investigated by Claude on the owner's MacBook Air (macOS 26.6) with Xcode 27.2's Instruments (SwiftUI and
Time Profiler via `xctrace`), `sample` and `scripts/app-cpu.sh` (release builds, Demo show, `--demo`). Starting point,
main at #273: idle 6.0 %, demo 36.7 %. Every row is a temporary change, measured, then undone; idle swings 1–2 points
between runs.

| Change | Idle | `--demo` |
|---|---|---|
| None (main at #273) | 6.0 % | 36.7 % |
| No `TimelineView` (cursor blink, clocks, show age) | 0.0 % | 29.7 % |
| Only the visible workspace drawn | 5.6 % | 29.7 % |
| Plain grid instead of `LazyVGrid` for the cells | 0.0 %* | 31.4 % |
| No right-click catcher NSViews in strips and tiles | – | 35.2 % |
| No `.help` tooltips | 4.8 % | 29.7 % |
| Window size fixed, resizability not tied to content | 7.3 % | 30.0 % |
| Playback area in its own `NSHostingView` | 0.0 %* | 31.6 % |
| **Tile stripe drawn on a CALayer, playbacks not publishing** | 6.5 % | **7.2 %** |

\* with the `TimelineView` change still in.

- [x] The Time Profiler puts two thirds of the busy samples in AttributeGraph (`UpdateStack::update`,
      `propagate_dirty`), under `NSHostingView.layout` → `ViewGraphRootValueUpdater.render`; CMDMX's own bodies are a
      few percent.
- [x] Any SwiftUI update in the main window costs about 10 ms, however small the view: a 2 Hz cursor blink and a 1 Hz
      clock alone keep the app at 6 % idle, one fader strip or one stripe at 20–30 Hz adds about 20 %. A bare SwiftUI
      app redrawing a bar at 60 Hz uses 0.4 %, so the cost grows with the size of the window's view graph.
- [x] A value set straight on a layer costs almost nothing: the stripes at 20 Hz on a CALayer, 7.2 %.
