# The engine's load on 266 fixtures, release build — P1-38 (2026-11-16)

M7 of the fifth gap review (`2026-11-08-gap-review.md`): a debug build took 78 % of a core on *Zondag 2* (266 fixtures),
10 % on *Demo* (38). This run measures a release build on a rig of the same size, and the debug build beside it on
the same show. Claude did every step on loopback; no app, no hardware, no lamps, no real show opened.

Setup: `main` at 86efb4a, `cmdmx-daemon` built with `cargo build --release` and `cargo build` in `subprojects/engine`,
on the owner's Mac (Mac16,12, Apple M4, 10 cores), with Chrome and other sessions running (load average about 2.7).
Show *Groot*, built over IPC in `/tmp/cmdmx-p138/Shows` from the Demo show, the same rig as the gap review's
*Zondag 2*: the 38 Demo fixtures on universe 1, 48 washes on 2, 96 RGBW pars on 3, 72 dimmers on 4 and 12
LED Par 56 on 5 (`patch.add` with `auto_groups`), 266 fixtures. Page 3 holds five playbacks with shapes, each Dimmer
at full plus: Circle and Rainbow on the 48 washes, Rainbow wave on the 96 pars, Dimmer wave on the 72 dimmers,
Sparkle on Demo group 1 (30 fixtures), Colour chase on the 12 pars. That is 258 of the 266 fixtures in a shape. The
file's output nodes were then edited to Art-Net `target` 127.0.0.1 and sACN `unicast` 127.0.0.1 on all five
universes, and the serial `auto` node was removed; the Demo file was deleted from the folder, so only *Groot* opened.

Method: a Python script in the session's scratchpad starts the daemon (`--show-dir --profiles-dir --ipc-port 7360
--no-serial`), waits 3 s, raises the faders, waits 5 s, then reads the process's CPU time (`ps -o time=`) before and
after 60 s: the average is CPU seconds over wall seconds. `ps -o %cpu=` every second gives the range. States:
1. **idle**: *Groot* open, every fader at 0, `--no-artnet --no-sacn`.
2. **busy**: `fader.set` level 1 on all 15 playbacks (the Demo's ten and the five above), `--no-artnet --no-sacn`.
3. **output**: as busy, with Art-Net and sACN on, both to 127.0.0.1; a listener on UDP 6454 and 5568 counts packets.
4. **client**: as output, with a WebSocket client connected all the time, as the app is (it gets the live-output
   deltas, IPC-58).

## Results
- [x] [Claude] Release, two runs of 60 s per state (% of one core):

  | State | Run 1 | Run 2 | `ps` range |
  | --- | --- | --- | --- |
  | idle | 7.5 | 6.6 | 3–10 |
  | busy | 12.6 | 11.3 | 5–16 |
  | output | 13.2 | 13.1 | 4–19 |
  | client | 13.4 | 13.0 | 4–19 |

  Memory 15 MB. Output: 200 packets/s on Art-Net and 200 on sACN, i.e. 40 frames/s on each of the five universes;
  9697 of the 12000 frames in 60 s differed from the frame before, so the shapes ran. The client got 20 messages/s.
- [x] [Claude] Debug, one run of 60 s per state: idle 36.3 %, busy 48.8 %, output 48.8 %, client 49.2 %; memory 22 MB.
- [x] [Claude] Verdict: the release engine takes about 13 % of one core with shapes on 258 fixtures, five universes on
  two protocols and a client connected, on a Mac with ten. With the app's own budget (UI-70: 15 % with `--demo`)
  the console stays under a third of one core. That is well under one core, so no budget criterion is added. The
  release build costs about a quarter of the debug build here, and the gap review's 78 % was a debug build with the
  app connected at v0.7.0.

## Found in the run
- The debug build did not keep up: 90 packets/s per protocol, 18 frames/s per universe instead of 40, and the client
  got 18 messages/s instead of 20. The release build held 40 Hz in every state. Debug builds are never shipped (the
  DMG builds the daemon with `--release`, `subprojects/app/scripts/make-dmg.sh`), so nothing follows from it; it only means a debug run on a large rig shows
  slower output than a service would.
- Idle is not free: with every fader at 0 the release engine still takes about 7 %, against 12 % with everything
  running. The tick works through every fixture each time, whether anything plays or not.

## Not run
- The app itself on this rig: the client in state 4 only receives. `scripts/app-cpu.sh` measures the app on the Demo.
- Fades of a cue list on 266 fixtures (a Go with fade time); the shapes above keep every value moving at 40 Hz,
  which is the heavier case.
- The Eurolite on serial: never on a run without the owner (`tests/hardware/church.md`).
