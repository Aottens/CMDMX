## Checks
- [x] I2: half. `@ v` is v % (`command.rs`), which is Titan's default (*Channel Levels*: two digits, 50 = 50 %). What differs:
  `@ @` is refused (the parser reads the second `@` as a level and fails), where Titan's Quick Reference gives full; and there
  is no single-digit mode (Titan's *Channel Levels* setting: 5 = 50 %).
- [x] I4: holds. A connected chase's crossfade is shown in the Go block ("120 BPM · xfade 50 %", `CueLists.swift`) and set
  only in Playback Options (`PlaybackOptions.swift`); BPM has a field there, crossfade has none, and no surface action
  reaches either. Titan: a connected chase has speed on the left wheel and crossfade on the right (*Chase Playback*,
  *Chase Options*).
- [x] I5: holds. The Cue list window is a plain `ScrollView` with no `ScrollViewReader` (`CueLists.swift`), so it never
  follows the current cue. Titan: Playback View scrolls to keep the active cue in sight; a cog sets how (*Cue List Playback*).
- [x] I7: holds. Direction is a Chase tab choice only (`PlaybackOptions.swift`); Go and Back on a running chase step without
  changing it (CUE-32). Titan: Prev Step and Next Step set the connected chase's direction, ↔ gives bounce and Review gives
  random (*Chase Playback*).
- [x] I8: holds. FX-25 multiplies every playback effect by *m* (`playback_effect` in `engine.rs`); no option. Titan: Playback
  Options › Effects › *Shape Size*: Fixed, Fader, HTP Fader.
- [x] I9: changed. Titan has no *Block Shapes* or *Solo Excluding Shapes* now: *search only*, the v14 release notes say *Mask
  Shapes* replaced Block Shapes, and the nearest to the second is the user setting *Swop Shapes* (all shapes stop on a Swop,
  or only intensity shapes; default all). On `main` a Swop stops no effect at all: `with_effect` in `engine.rs` never looks at
  `swop_owner`, so another playback's dimmer chase keeps running through a Swop, against PBK-27 ("every other active
  playback's HTP contribution is 0"). No playback can stop another's effect (ENG-15: one effect per attribute, and a relative
  effect runs around any base).
- [x] K4: holds. `cuelist.go` on a running list starts the next cue whatever the time since the last Go (CUE-10); nothing in
  core, daemon or control guards it. Titan documents no guard.
- [x] K5 and L4: hold. A new playback and a new cue get an empty legend (`playback.rs`); only the icon is automatic (PBK-32).
  Titan: a legend can be typed while recording (*Creating a Cue List*); *Auto Legend* (User Settings, Palettes tab, default
  on) gives new items generated legends, which the page does not tie to cues. An automatic cue legend is our own choice.
- [x] M4: holds. `cue.renumber` and `cue.copy` take one cue and one number in the same list (CUE-08); CUE-63 left several
  out. Titan: Copy or Move with a block of cues (Thro, And, Not, or a box dragged in Playback View) `@ n` makes a block from n;
  `@ @` puts it at the end; another playback's Select as the target puts it in that list (*Editing Cue Lists*).
- [x] The *Absent and untracked* list under I (Record By Fixture, Temporary Speed, Tempo Units, Speed Multiplier and the rest)
  is not in this batch: no point of it was seen in a run, and none is daily.
