`tests/manual/app-main-screen.md` *Esc, one level up* (UI-44), *Opening a screen disarms* (UI-45) and *Lock from anywhere* (UI-48), at home without lamps.
Claude drove the app with a real mouse and real keys by full-screen control; the owner approved it. A listener on port 6454 read Art-Net.

Setup: this branch, debug bundle, app with `HOME` in a temp folder and `-consoleMode NO`, first `-keysLive NO`, then a restart with `-keysLive YES`, against a daemon with
`--show-dir` and `--profiles-dir` in a temp folder and `--no-sacn --no-serial`, Demo show. Handle 1.2 got a cue list of two cues.

## Esc (UI-44)
With Keys off:
- [x] Record, a function (Update), the Palette softkeys with a typed line, the Cue softkeys: Esc does what Exit does. With nothing left it does nothing.
- [x] Patch, Output, Control, Show, Playback Options: Esc goes back to the workspace. A typed `7` waits behind Patch; the next Esc empties it.
- [x] Patch: Confirm remove waiting, Esc leaves; back on Patch nothing waits, still 30 fixtures.
- [x] Profile editor: clean, Esc closes it. With a changed field, the first Esc leaves the field, the second asks "Discard changes?", Esc on that dialog stays in the editor with the text.
- [x] Cue view: Esc goes back to the Cue list.
- [x] Playback Options, Fade in: `9`, Esc shows 0 again and the cue keeps 0, and the screen stays. `3`, Tab sends 3 (the list shows 3/0), the next Esc leaves the next field, the next the screen.
- [x] Patch search: `par`, Esc gives up focus and leaves `par` there; the next Esc leaves the screen.
- [x] Messages sheet and a legend sheet: Esc closes only the sheet. Lock prompt: Esc cancels. Learn: Esc ends it and the Control screen stays.

With Keys on:
- [x] Record: Esc disarms. `7` from the keyboard, Esc empties the line. Show: Esc leaves.
- [x] Control, OSC Port: `1234`, Esc shows 8000 again and it stays 8000 after reopening. The next Esc leaves.

Art-Net:
- [x] Flash held on 1.1 with the mouse, Esc: channel 1 stays at 255 until the release. The only other changes in the run are the programmer's own levels and the daemon restart; no Esc changed the output.

## Not run
- Deck focus on Control: no deck connected. The hidden cancel button holds the branch; by reading only.
- Esc held: `hold_key` kept a typed line on leaving Patch, but a tool's held key may send no repeats, so this rests on `event.isARepeat` by reading.
- BPM in the Cue list and a number on Shapes: the same two lines as the fields that ran; by reading. Cue view with Remove waiting: by reading, `cueRemoveConfirm` is in `modesOpen`.
- The Control dot: no enabled control device. It sets `ui.screen` as the other dots do, and the `didSet` covers it.

## What the run showed
- The Control screen draws its bindings late in this debug build (1 to 5 s). An Esc pressed in that time takes effect once it is drawn, so a screenshot just after still shows the screen. Not a lost press, though a release build was not tried.
- `UI-44` is written for a field with an edit. Form fields (Patch, Show, the profile editor) hold their text until the screen goes: nothing was applied, and the spec line now says so. The profile editor counts as a level of its own, also added to the line.
